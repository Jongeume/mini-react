# ADR 0004. 마이크로태스크 배칭 (v2)

상태: 채택 후 ADR 0006(v4 useRef)으로 오목 데모의 기본 엔진 자리를 넘김 · 2026-11-11

## 배경

- ADR 0003(v1)은 엔진이 감싼 핸들러 안의 setter 만 묶습니다.
- 핸들러 밖의 setter 는 setter 마다 렌더합니다. 오목 데모의 예는 다음과 같습니다.
	- 타이머가 1초마다 setter 를 둘 부르면 렌더가 2번 일어납니다.
	- 저장 동작에서 `await` 뒤의 setter 둘도 렌더가 2번 일어납니다.
- 묶는 기준을 "엔진이 붙인 핸들러가 끝날 때"에서 "지금 실행 중인 코드가 모두 끝날 때"로 넓히면 이 경로들도 한 번으로 줄어듭니다. React 18 의 자동 배칭과 같은 방향입니다.
- v1 과 같은 앱(오목)에서 나란히 비교할 수 있어야 했습니다.

## 결정

setter 는 값만 저장하고 렌더는 마이크로태스크로 한 번만 예약합니다. 이벤트 안과 밖을 구분하지 않습니다.

| 요소 | 동작 | 구현 위치 |
| --- | --- | --- |
| setter | 값을 바로 저장하고 `queueDeferred` 로 줄을 세운 뒤 컴포넌트를 예약 목록(`Set`)에 넣습니다. 예약 목록이 처음 생길 때만 `queueMicrotask(flushFromMicrotask)` 를 한 번 겁니다(없으면 `Promise.resolve().then`). | `engines/v2-microtask/hooks.js` `makeSetter`, `schedule` |
| 핸들러 감싸기와 `batch` | 제거합니다. 이벤트 경계가 필요 없기 때문입니다. | `component.js` (`wrapHandler` 없음), `hooks.js` (공개 API 에 `batch` 없음) |
| 같은 값 setter | 렌더 없이 예약만 합니다. 예약을 비울 때 밀린 갱신이 없으면 `resyncForms` 로 입력칸만 상태에 맞춥니다. | `hooks.js` `makeSetter`, `component.js` `flushBatched` |
| 커밋 중 setter | v1 과 같습니다. 예약하지 않고, 지금 도는 `settle` 이 커밋 뒤 이어서 갱신합니다. | `hooks.js` `makeSetter`, `component.js` `settle` |
| `flushSync(fn)` | `fn` 안의 setter 를 기다리지 않고 그 자리에서 반영하고 돌아옵니다. 예외는 부른 쪽으로 던집니다. | `hooks.js` `flushSync` |
| 예약 렌더의 예외 | 부른 쪽이 이미 끝났으므로 던질 곳이 없습니다. 값은 기존 `restoreQueued` 로 되돌리고, 예외는 `reportError`(없으면 `console.error`)로 보고합니다. | `hooks.js` `flushFromMicrotask` |
| `mount`, 공개 `update()` | 지금처럼 동기입니다. | `component.js` |

- `engines/v2-microtask/` 는 `vdom.js`, `diff.js`, `patch.js` 가 v1 과 같고, `hooks.js` 와 `component.js` 만 다릅니다.
- 오목 데모는 `omok/loader.js` 가 주소의 `?engine=` 값으로 엔진 폴더를 고릅니다. 기본값은 당시 `v2-microtask` 였고 지금은 `v4-ref` 입니다(ADR 0006). `v1-batch`, `v0` 도 고를 수 있습니다.

## 고려한 대안

| 대안 | 얻는 것 | 내주는 것 | 판단 |
| --- | --- | --- | --- |
| 가. 별도 엔진 폴더(`engines/v2-microtask`)에 구현하고 전용 비동기 테스트를 둠 | v1 의 동기 테스트를 건드리지 않고, 오목에서 엔진만 바꿔 바로 비교할 수 있습니다. | 엔진 코드가 버전별로 복제됩니다. | 채택 |
| 나. v1 작업본 자체를 v2 로 바꿈 | 코드 복제가 없습니다. | 동기를 전제로 한 기존 테스트 100개 안팎을 `await` 로 옮겨야 합니다. | 기각 |
| 예약 렌더의 예외를 그대로 던짐 | 코드가 단순합니다. | 던질 호출 스택이 없어 예외가 사라지거나 처리되지 않은 오류가 됩니다. | 값을 되돌리고 `reportError` 로 보고 |
| `flushSync` 를 제공하지 않음 | API 가 작습니다. | setter 직후 바뀐 DOM 을 읽어야 하는 코드가 막힙니다. | 제공 |

## 결과와 비용

오목 데모에서 엔진 버전을 바꿔 센 커밋(렌더) 수입니다.

| 동작 | v0 | v1 | v2 (이 ADR) |
| --- | --- | --- | --- |
| 착수 (setter 2) | 2 | 1 | 1 |
| 전체 초기화 (setter 5, 측정 때 하나는 같은 값) | 4 | 1 | 1 |
| 타이머 1초 (엔진 이벤트 밖) | 2 | 2 | 1 |
| 저장 (시작 1 + `await` 뒤 2) | 3 | 3 | 2 |

| 얻은 것 | 낸 비용 |
| --- | --- |
| 이벤트 밖 경로(타이머, `await` 뒤, 앱이 직접 붙인 리스너)까지 묶입니다. | setter 를 부른 직후에는 DOM 이 아직 옛 모습입니다. 바로 읽어야 하면 `flushSync` 를 써야 합니다. |
| 앱 코드를 바꾸지 않아도 됩니다. | 예약된 렌더의 예외는 부른 쪽이 받을 수 없습니다. 보고만 되고, v1 과 계약이 다릅니다. |
| 핸들러를 감싸는 코드와 `batch` 예외 규칙이 사라져 엔진이 단순해집니다. | `flushSync` 를 타이머처럼 자주 도는 곳에 쓰면 배칭의 이점을 버립니다. |
| 중간 상태가 렌더되지 않는 점은 v1 과 같습니다. | 단위 테스트의 기준 엔진은 여전히 v1(동기)이고, v2 는 전용 비동기 테스트만 가집니다. |

## 검증

`npm test` 를 2026-11-11 에 실행했을 때 전체 203개가 통과했습니다(실패 0). v2 전용 테스트는 `test/v2-microtask.test.js` 이고 `engines/v2-microtask/` 의 `vdom.js`, `hooks.js`, `component.js` 를 불러옵니다.

| 확인하는 것 | 테스트 이름 |
| --- | --- |
| 예약 후 한 번 | "setter 두 개 → 부른 직후엔 커밋 0, 마이크로태스크 뒤 커밋 1 · 두 값 반영" |
| 누적 | "함수형 +1 세 번 → +3, 커밋 1" |
| 엔진 이벤트 밖 | "타이머 콜백 안 setter 두 개도 커밋 1 (엔진 이벤트 밖)" |
| 클릭 핸들러 | "클릭 핸들러 안 setter 두 개 → 클릭 직후 0, 뒤에 커밋 1" |
| `flushSync` | "flushSync → 돌아온 직후 반영 · 커밋 1, 뒤에 추가 커밋 없음", "flushSync 안 렌더 예외는 부른 쪽으로 던지고 값을 되돌린다" |
| effect 연쇄 | "커밋의 effect 가 setter → 후속 커밋 1 더, 최종값 반영" |
| 예약 렌더의 예외 | "예약된 렌더 예외 → 값을 되돌리고 오류를 보고한다 (부른 쪽은 이미 끝남)" |
| 정리 | "예약 뒤 destroy → 렌더하지 않는다" |
| 같은 값 | "같은 값 setter 만 있으면 커밋 0, 제어 input 은 상태 값으로 돌아온다" |

- 비교 대상이 되는 v1 쪽 기대값은 `test/omok-page.test.js` "타이머 1초(엔진 이벤트 밖)의 setter 두 개는 지금 엔진에서 커밋 2회다 ..." 에 고정되어 있습니다. 이 테스트는 `engines/v1-batch/` 를 불러옵니다.
- 위 결과 표의 v2 열(착수, 전체 초기화, 저장)은 이 저장소의 자동 테스트로는 확인되지 않습니다. `test/omok-page.test.js` 가 v2 엔진을 불러오지 않기 때문입니다. 타이머 열은 `test/v2-microtask.test.js` 의 타이머 테스트가 같은 성질을 확인합니다.
- 기존 테스트의 기대값을 바꾸지 않는다는 것이 이 변경의 조건이었고, v2 는 별도 폴더에 있어 v1 테스트가 대상으로 삼는 코드를 건드리지 않습니다.

## 하지 않은 것

| 항목 | 이유 |
| --- | --- |
| v1 작업본을 v2 로 교체 | 동기 테스트를 대량으로 옮겨야 하고, v1 은 비교 대상으로 남겨야 합니다. |
| `key` 기반 재정렬, `useRef`, 안정된 핸들러(`useCallback` 에 해당) | 배칭과 별개의 개선입니다. 이벤트만 바뀐 `PROPS` patch 는 v2 에서도 남습니다. |
| 우선순위(lane)와 동시성 렌더링 | React 18 의 방향만 따르고 구조는 따라가지 않았습니다. 이 구현은 예약과 한 번의 비우기까지만 합니다. |
| `mount` 와 공개 `update()` 의 비동기화 | 처음 그리기와 명시적 갱신은 동기로 두어 호출 규약을 유지했습니다. |
| `flushSync` 의 기본 사용 | setter 직후 DOM 을 읽어야 할 때만 쓰는 예외적 수단입니다. |
