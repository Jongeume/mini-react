# ADR 0003. 이벤트 경계 배칭 (v1)

상태: 채택 후 ADR 0004(v2 마이크로태스크 배칭)로 기본 엔진 자리를 넘김 · 2026-11-11
`engines/v1-batch/` 는 v2 와 비교하기 위한 엔진으로, 그리고 단위 테스트의 기준 엔진으로 유지됩니다.

## 배경

- 과제의 중점 포인트 중 하나는 "여러 상태 변경을 한 번에 처리하는 방법"(Batching, 선택 과제)입니다.
- ADR 0002 의 기준선(`engines/v0`)은 setter 를 부를 때마다 즉시 렌더합니다.
- 오목 데모에서 돌 하나를 두면 setter 가 둘(판 기록, 현재 수) 불려 렌더가 2번 일어납니다.
- 같은 이유로 전체 초기화는 setter 가 5개입니다. 값이 그대로인 setter 는 렌더하지 않으므로, 측정한 상태(두 수 · 시간 흐름 · 저장 없음)에서는 렌더가 4번 일어납니다.
- 중간 상태가 렌더되는 문제도 있었습니다. 전체 초기화에서 `history` 만 먼저 바뀐 값으로 렌더하면 "기록은 1개인데 현재 수는 5" 인 상태가 만들어지고, 이 상태로 렌더하다 예외가 난 적이 있습니다.
- 갱신은 계속 동기여야 하고, 기존 테스트의 기대값은 바꾸지 않는다는 조건을 두었습니다.

## 결정

엔진이 `on*` 핸들러를 감싸서, 핸들러 안에서 부른 setter 를 모았다가 핸들러가 끝날 때 컴포넌트마다 한 번만 갱신합니다.

| 요소 | 동작 | 구현 위치 |
| --- | --- | --- |
| `batch(fn)` | 깊이 카운터를 올리고 `fn()` 을 실행합니다. `finally` 에서 깊이를 내리고, 가장 바깥(깊이 0)일 때만 모인 컴포넌트 목록을 꺼내 갱신합니다. | `engines/v1-batch/hooks.js` |
| setter 분기 | 렌더 중이면 예외, 없어진 컴포넌트면 무시, 같은 값이면 입력칸만 맞추고 종료, 그 외에는 값을 저장합니다. 그다음 커밋 중이거나 배칭 중이면 `queueDeferred` 로 줄을 세우고, 아니면 즉시 `update` 합니다. | `hooks.js` `makeSetter` |
| 핸들러 감싸기 | 펼치기 단계에서 `on` 으로 시작하는(대소문자 무관) 함수 props 를 `batch` 로 감쌉니다. 원래 함수마다 감싼 함수를 하나만 만들어 WeakMap 에 두므로, 같은 핸들러는 같은 감싼 함수가 되어 diff 결과가 달라지지 않습니다. | `component.js` `wrapHandler`, `wrapProps` |
| 반영 | 목록의 컴포넌트마다 `idle` 상태이고 없어지지 않았으면 `settle` 로 갱신합니다. 기존의 값 되돌리기, 50회 연쇄 제한, effect 예외 모으기를 그대로 씁니다. 커밋 중인 컴포넌트는 건너뜁니다(바깥 `settle` 이 처리 중입니다). | `component.js` `flushBatched` |
| 예외 | 깊이는 `finally` 에서 반드시 되돌립니다. 핸들러가 던져도 그 전에 저장한 상태는 반영합니다. 둘 다 던지면 핸들러 예외가 이기고 반영 중 예외는 그 예외의 `heldErrors` 에 붙입니다. 반영 중 예외만 있으면 그대로 던집니다(여럿이면 `AggregateError`). | `hooks.js` `batch`, `throwFlushErrors` |

## 고려한 대안

| 대안 | 얻는 것 | 내주는 것 | 판단 |
| --- | --- | --- | --- |
| 가. 엔진이 핸들러를 감싸는 이벤트 경계 | 앱 코드가 그대로이고 갱신이 동기로 유지되며, 기존 테스트가 유지됩니다. | 엔진이 감싼 핸들러 밖의 setter 는 묶이지 않습니다. | 채택 |
| 나. 앱이 직접 `batch()` 를 호출 | 구현이 가장 작습니다. | 앱이 매번 기억해야 하고 엔진의 개선이 아닙니다. | 기각 |
| 다. 마이크로태스크 배칭 | 모든 경로(타이머, `await` 뒤 포함)가 묶입니다. | 갱신이 비동기가 되어 테스트와 예외 계약이 크게 바뀝니다. | 이 단계에서는 보류, ADR 0004 에서 별도 엔진으로 구현 |

## 결과와 비용

오목 데모에서 엔진 버전을 바꿔 센 커밋(렌더) 수입니다.

| 동작 | v0 | v1 (이 ADR) |
| --- | --- | --- |
| 착수 (setter 2) | 2 | 1 |
| 전체 초기화 (setter 5, 측정 때 하나는 같은 값) | 4 | 1 |
| 타이머 1초 (엔진 이벤트 밖, setter 2) | 2 | 2 |
| 저장 (시작 1 + `await` 뒤 2) | 3 | 3 |

| 얻은 것 | 낸 비용 |
| --- | --- |
| 이벤트 한 번에 렌더 한 번이라 함수 실행, diff 비교, patch 명령이 함께 줄어듭니다. | 엔진 이벤트 밖(타이머, `await` 뒤, 앱이 직접 붙인 리스너)의 setter 는 묶이지 않습니다. |
| 중간 상태가 렌더되지 않습니다. | 한 이벤트 안에서 값이 A 에서 B, 다시 A 로 돌아와도 렌더는 한 번 일어납니다(patch 는 0개일 수 있습니다). |
| 갱신이 동기라 클릭 직후 DOM 이 이미 바뀌어 있고, 예외는 호출한 쪽으로 전달됩니다. | 핸들러를 감싸는 코드(`wrapHandler`, `wrapProps`)와 `batch` 예외 규칙이 엔진에 추가되었습니다. |

## 검증

`npm test` 로 실행하며, 두 파일 모두 `engines/v1-batch/` 를 대상으로 합니다.

| 확인하는 것 | 파일 · 테스트 이름 |
| --- | --- |

| 예외 계약 | `test/batch.test.js` "batch 안 setter 뒤 예외 → assert.throws 로 같은 예외, 값 반영 · 커밋 1회, 그 뒤 batch 가 다시 정상 동작", "batch 안 렌더 예외 → 예외가 나오고 batch 안에서 바꾼 값이 모두 되돌려짐" |
| 예외가 겹칠 때 | `test/batch.test.js` "batch 안 핸들러도 던지고 컴포넌트 둘의 렌더도 던지면 → 핸들러 예외가 이기고 heldErrors 에 덧붙임, 값은 모두 되돌림", "batch 핸들러는 정상인데 컴포넌트 둘의 렌더가 던지면 → AggregateError 2개, 값은 모두 되돌림" |
| 커밋 뒤 effect 연쇄 | `test/batch.test.js` "batch 커밋의 effect 가 setter → 커밋 2회, 최종값 반영", "batch 커밋의 effect 가 끝없이 setter → update loop 예외, 값은 되돌림" |
| 재진입 | `test/batch.test.js` "effect 가 엔진 버튼을 click() 해도 다시 들어가 그리지 않는다" |

| 오목에서의 커밋 수 | `test/omok-page.test.js` "칸을 누르면 돌이 놓이고 차례가 바뀐다 ... 착수 setter 두 개가 커밋 1회로 묶인다", "전체 초기화의 setter 다섯 개는 커밋 1회로 묶인다", "타이머 1초(엔진 이벤트 밖)의 setter 두 개는 지금 엔진에서 커밋 2회다 ..." |

- 위 표의 v0 열은 자동 테스트가 아니라 엔진 버전을 바꿔 센 값입니다. 자동 테스트는 v1 열(착수 1, 전체 초기화 1, 타이머 2)을 확인합니다.
- 타이머 1초가 커밋 2회라는 테스트는 이 엔진의 한계를 고정하는 테스트이며, ADR 0004 의 비교 기준입니다.
- 저장 동작(`await` 뒤)의 커밋 3회는 이 저장소의 자동 테스트로 확인되지 않습니다.

## 하지 않은 것

| 항목 | 이유 |
| --- | --- |
| 마이크로태스크 배칭 | 갱신이 비동기가 되어 계약이 바뀌므로 ADR 0004 에서 별도 엔진으로 다룹니다. |
| 엔진 이벤트 밖 setter 묶기 | 이 결정의 한계로 받아들이고, 타이머 커밋 2회를 테스트로 고정했습니다. |
| `key` 기반 재정렬 | 배칭과 별개의 문제입니다. |
| 컴포넌트 구조 변경 | Hook 과 상태는 루트에서만 쓰고 자식은 props 만 받는 제약을 그대로 유지합니다. |
| ADR 0001 의 파일(`vdom.js`, `diff.js`, `patch.js`, `history.js`) 수정 | 배칭은 `hooks.js` 와 `component.js` 안에서 끝났습니다. |
| 타입 검사 도입 | 이 결정의 범위 밖입니다. |
