# ADR 0001. Virtual DOM, Diff, Patch 의 기본 구조

상태: 채택 · 2026-11-06

## 배경

- 과제의 첫 단계는 Virtual DOM 을 만들고, 이전 트리와 새 트리를 비교해서 실제 DOM 의 바뀐 곳만 고치는 것입니다.
- 이 단계의 코드는 이후 컴포넌트와 Hook 단계에서 그대로 재사용되므로, 입력이 무엇이든 "VDOM 두 개를 받아 변경 목록을 만든다"는 형태여야 했습니다.
- 구조는 단순하게(객체, 배열, O(n) 순회) 두고 정확성을 우선하기로 했습니다.
- 정확성은 "위치가 어긋나면 조용히 틀리지 않고 예외를 낸다"는 뜻입니다.

## 결정

한 줄 요약: Virtual DOM 은 순수한 데이터이고, 실제 DOM 은 번호(path)로 찾습니다.

| 영역 | 결정 | 구현 위치 |
| --- | --- | --- |
| 노드 모양 | 모든 노드가 `{ type, props, children }` 세 칸입니다. 텍스트는 `{ type: '#text', props: { nodeValue }, children: [] }` 입니다. | `engines/v1-batch/vdom.js` |
| Diff | 같은 번호의 자식끼리 재귀로 비교합니다. 분기는 5갈래입니다(없음, 사라짐, 태그 다름, 글자, 같은 태그). | `engines/v1-batch/diff.js` `walk` |
| 변경 목록 | `CREATE`, `REMOVE`, `REPLACE`, `TEXT`, `PROPS` 다섯 종류이고, 각 항목은 `type`, `path` 와 필요한 재료를 가집니다. | `diff.js`, `patch.js` |
| Patch | `path` 를 따라 `childNodes[i]` 로 내려가(`findNode`) 그 노드만 고칩니다. 못 찾으면 예외입니다. | `engines/v1-batch/patch.js` |
| 새 노드 만들기 | `createElement` 로 재귀 생성합니다. `innerHTML` 은 쓰지 않습니다. | `vdom.js` `render` |
| 공백과 주석 | 줄바꿈이 든 공백 텍스트와 주석은 버립니다. 단 `<pre>`, `<textarea>` 안은 남깁니다. | `vdom.js` `domToVdom` |
| 시작 맞추기 | 로드할 때 실제 영역을 VDOM 대로 한 번 다시 그려 DOM 과 VDOM 을 1:1 로 맞춥니다. | `patch.js` `mount` |
| 기록 | 배열과 현재 번호로 State History 를 두고, 넣을 때와 꺼낼 때 트리를 복사합니다. | `phase1/history.js` |

- 한 바퀴는 `phase1/app.js` 의 `onPatch` 가 이어 줍니다: `htmlToVdom`, `diff`, `applyPatches`, `history.push`.
- 뒤로 가기와 앞으로 가기(`travel`)도 같은 길입니다. 기록의 VDOM 과 지금 화면의 VDOM 을 비교해 반영합니다.
- 엔진 폴더 세 곳(`v0`, `v1-batch`, `v2-microtask`)의 `vdom.js`, `diff.js`, `patch.js` 는 내용이 같습니다. 검증 페이지(`phase1.html`)는 `engines/v1-batch/` 를 불러옵니다.

## 고려한 대안

| 쟁점 | 대안 | 얻는 것 | 내주는 것 | 판단 |
| --- | --- | --- | --- | --- |
| 텍스트 노드 | 객체 `#text` | 모든 노드가 같은 세 칸이라 비교와 렌더에 "문자열인가" 분기가 없습니다. | 모양이 조금 깁니다. | 채택 |
| | 그냥 문자열 | 짧고 React 와 비슷합니다. | 함수마다 분기가 생깁니다. | 기각 |
| 공백 텍스트 | 줄바꿈 포함분만 버림 | 들여쓰기가 노드가 되어 생기는 "바뀜" 오탐이 없습니다. 같은 줄 공백(`<b>a</b> <i>b</i>`)은 보존됩니다. 테스트 영역을 들여써 보여 줘도 다시 읽으면 같은 VDOM 입니다. | `</label>\n<button>` 사이처럼 줄바꿈만 있는 공백은 화면에서도 사라집니다. | 채택 |
| | 모두 버림 | 규칙이 가장 단순합니다. | 단어 사이 공백이 사라집니다. | 기각 |
| | 모두 남김 | 원본에 충실합니다. | 들여쓰기만 바꿔도 diff 가 생깁니다. | 기각 |
| 주석 | 버리고, 끊긴 글자는 합침(`a<!--x-->b` 는 `"ab"`) | 노드 종류가 늘지 않고, HTML 로 쓴 뒤 다시 읽어도 개수가 같습니다. | 원본 주석 정보를 잃습니다. | 채택 |
| | 남김 | 원본에 충실합니다. | 모든 함수가 `#comment` 를 알아야 합니다. | 기각 |
| 노드 찾는 법 | 번호(path)로 걷기 | VDOM 이 순수 데이터라 기록에 그대로 저장, 복사할 수 있습니다. 이후 매번 새로 만드는 트리에 옛 연결을 넘길 필요가 없습니다. | DOM 과 VDOM 이 1:1 이어야 합니다. 번호가 밀리지 않게 REMOVE 는 뒤 번호부터 냅니다. | 채택 |
| | VDOM 에 실제 노드를 붙여 둠 | 바로 찾습니다. | 객체가 데이터가 아니게 되고, 기록이 옛 노드를 가리킵니다. | 기각 |
| 비교 알고리즘 | 같은 자리끼리 비교(O(n)) | 단순하고 빠릅니다. 태그가 다르면 통째로 바꾼다는 React 의 가정과 같습니다. | 변경 목록이 최소가 아닐 수 있습니다. | 채택 |
| | 최적 트리 비교 | 변경 목록이 최소입니다. | O(n³) 수준의 비용입니다. | 기각 |
| 새 노드 생성 | `createElement` 재귀 | 글자가 HTML 로 해석되지 않아 XSS 를 피하고, SVG 이름공간을 지킬 수 있습니다. | 코드가 길어집니다. | 채택 |
| | `innerHTML` | 짧습니다. | 입력 글자가 HTML 로 실행될 수 있습니다. | 기각 |

## 결과와 비용

| 얻은 것 | 낸 비용 |
| --- | --- |
| diff 는 목록을 만들기만 하고 patch 는 목록을 쓰기만 하므로, 한쪽을 고쳐도 다른 쪽은 그대로입니다. | 로드할 때 실제 영역을 한 번 다시 그립니다(`mount`). |
| 컴포넌트 단계에서 `diff`, `applyPatches`, `render` 를 그대로 재사용했습니다. 입력이 VDOM 이기만 하면 됩니다. | 다른 코드가 실제 DOM 을 몰래 바꾸면 위치가 어긋납니다. 그때는 예외가 나고, 검증 페이지는 이전 화면으로 되돌립니다. |
| 입력 중인 값과 포커스가 바뀌지 않은 노드에서는 유지됩니다. | 트리 두 벌을 메모리에 두고 매번 O(n) 비교를 합니다. |
| 핵심 자료구조가 객체와 배열뿐이라 읽기 쉽습니다. | `vdom.js` 는 핵심 변환보다 경계 사례(이름공간, 폼 상태, `<template>`) 처리가 더 깁니다. |
| 함수 속성(`onClick` 등)은 같은 함수일 때만 "바뀌지 않음"으로 보며, 바뀌면 옛 리스너를 떼고 붙입니다. | 이 규칙은 이후 ADR 0002 의 이벤트 핸들러 비용으로 이어집니다. |

## 검증

테스트는 `npm test` (Node 내장 `node:test`, DOM 은 `jsdom`) 로 실행합니다. 아래 파일은 모두 `engines/v1-batch/` 의 모듈을 `require` 합니다.

| 확인하는 것 | 파일 · 테스트 이름 |
| --- | --- |
| 노드가 세 칸 모양이고 왕복이 안전함 | `test/vdom.test.js` "텍스트 노드도 요소와 같은 세 칸 모양이다", "render → domToVdom 을 거치면 원래 VDOM 이 그대로 나온다 (왕복)" |
| 공백 규칙 | `test/vdom.test.js` "들여쓰기 공백(줄바꿈 포함)은 버리고, 같은 줄의 공백 한 칸은 남긴다", "`<pre>` 안의 공백 · 줄바꿈은 그대로 남긴다" |
| 주석 규칙 | `test/vdom.test.js` "주석은 버린다", "[C1-2] 주석으로 끊긴 글자는 한 덩어리로 합쳐 왕복해도 같다" |
| 글자가 HTML 로 해석되지 않음 | `test/vdom.test.js` "render 는 텍스트를 HTML 로 해석하지 않는다 (innerHTML 미사용)" |
| 분기 5갈래와 변경 종류 | `test/diff.test.js` "같은 트리면 patches 가 비어 있다", "텍스트만 바뀌면 TEXT 하나 (경로 포함)", "태그가 바뀌면 REPLACE 하나, 그 안은 더 비교하지 않는다" |
| 자식 수가 다를 때 번호 규칙 | `test/diff.test.js` "자식이 늘면 뒤에 CREATE (앞 번호부터)", "자식이 줄면 뒤 번호부터 REMOVE (번호 밀림 방지)" |
| 바뀐 노드만 고침 | `test/patch.test.js` "TEXT: 글자만 바꾸고 노드는 그대로 둔다 (같은 객체)", "patches 가 비면 DOM 을 건드리지 않는다" |
| 어긋남을 예외로 알림 | `test/patch.test.js` "DOM 과 VDOM 이 어긋나면 알 수 있는 에러를 낸다" |
| 가장 강한 증거 | `test/patch.test.js` "무작위 트리 500쌍: patch 결과를 다시 읽으면 새 VDOM 과 같다" |
| 기록 규칙 | `test/patch.test.js` "History: push · back · forward, 끝에서는 null", "History: 뒤로 간 다음 push 하면 앞으로가기 기록을 버린다", "History: 넣은 객체 · 꺼낸 객체를 고쳐도 기록은 안 바뀐다" |
| 이벤트 함수 속성(이후 단계 대비) | `test/diff.test.js` "이벤트 함수는 같은 함수면 그대로, 다른 함수면 set (Phase 2 대비)", `test/vdom.test.js` "setProp: on… 함수는 이벤트로 붙이고, 바꾸면 옛 함수를 떼어 낸다 (Phase 2 대비)" |
| 이름공간, 폼 요소, 스크립트 제거 등 경계 사례 | 테스트 이름이 `[C1-1]` 처럼 `[C` 로 시작하는 항목입니다. 리뷰 중 발견되어 추가된 사례입니다(`test/vdom.test.js`, `test/diff.test.js`, `test/patch.test.js`). |

- 검증 페이지(`phase1.html`, `phase1/app.js`)에서는 patch 건수와 실제 DOM 변경 수(`MutationObserver`)를 나란히 보여 줍니다. 두 수는 같지 않을 수 있습니다(`PROPS` 1건에 속성 2개면 변경 2건).
- 위 테스트에는 브라우저에서만 확인되는 부분(깜빡임 표시, 실제 입력)이 포함되지 않습니다.

## 하지 않은 것

| 항목 | 이유 |
| --- | --- |
| `key` 비교와 `MOVE` patch | 단계 마감을 우선했습니다. 목록 맨 앞에 넣으면 뒤 항목이 모두 `TEXT` 로 바뀌고 끝에 `CREATE` 가 생기지만 결과는 맞습니다. `test/diff.test.js` "목록 맨 앞에 넣으면 같은 번호끼리 비교라 뒤 항목들이 TEXT 로 바뀌고 끝에 CREATE" 가 이 동작을 고정합니다. |
| `<plaintext>` 지원 | 닫을 수 없는 폐기된 요소입니다. |
| MathML 의 드문 경계 | `annotation-xml encoding="text/html"` 안의 HTML 과 `<mi>` 안의 `mglyph` 는 이름공간이 파서와 다를 수 있습니다. 거의 쓰이지 않아 범위 밖으로 두었습니다. |
| 사용자가 실제 영역에서 직접 바꾼 값을 VDOM 에 반영 | 이 단계의 VDOM 은 테스트 영역의 HTML 에서만 만듭니다. 값 관리는 컴포넌트 단계의 상태로 다룹니다. |
| ES 모듈 사용 | `file://` 로 연 페이지에서는 브라우저가 ES 모듈을 막습니다. 즉시 실행 함수와 `window.MiniReact` / `module.exports` 를 함께 씁니다. 같은 파일을 Node 테스트에서도 `require` 로 읽을 수 있습니다. |
